# AXIS-FALL (Unity project "ClaudeTest")

Multiplayer FPS where portals change your gravity. Unity 6000.6.8f1, URP, Netcode for GameObjects 2.13.3,
Unity Relay (com.unity.services.multiplayer 2.4.1), old Input Manager. All game code is in `Assets/GravityPortals`.
GitHub: benslav/AXIS-FALL-W-AI (branch `main`).

## How the game works (non-obvious rules)

- **Portal gravity rule** (`Portal.GravityAfterPass`): your *fall direction carries through the portal*
  (TransferRotation applied to gravity), snapped to the nearest axis within 30 degrees. Drop into a floor portal ->
  you land on the surface the exit faces; walk through a door upright -> you come out upright relative to the exit
  door. Players, props, bolts and the server's validation all use this one function. The user iterated on this
  rule a lot; don't change it without being asked.
- **Seamless passes**: you arrive at the exact mirrored spot (no push-out; the exit surface stays ignored while
  you step out). The local player's camera uses its own smoothing (`GravityPlayerController.RenderPosition`,
  Rigidbody interpolation off locally) that is carried through the portal on a pass. Portal cameras match the main
  camera's HDR/MSAA, skip post-processing, clip exactly at the exit surface (oblique matrix, never the plain
  fallback), and the surface switches to `ZTest Always` in the last 15 cm so the wall behind can't flash in past
  the near clip. Each of these fixed a visible blip the user reported; keep them.
- **Networking**: owner-simulated movement, server-validated (speed, gravity only changes via a real portal pass,
  pass must start at the entrance and end at its exit). Server-authoritative hits with lag compensation
  (`NetworkGravityPlayer.StateAt`). Props/bolts are server-simulated.
- **Session flow**: `MainMenu` scene (build index 0) is also the lobby. Its NetworkManager persists across maps
  (`SessionFlow`); the copies that arrive with each map scene are destroyed (`NetworkHud.Awake`,
  `SessionFlow.Awake`). Players are spawned by `SessionFlow` when a map finishes loading (session NetworkManager
  has no PlayerPrefab). Opening a map scene directly still uses that map's own NetworkManager + `NetworkHud`
  (direct IP / Relay) for testing. `ConnectionApproval` does version check + names for both paths.

## Maps are generated by editor scripts

Every map scene is built by a script in `Assets/GravityPortals/Editor` (Tools > Gravity Portals > Build ...).
Each has an `EditorPrefs` version key; bumping its `Version` const makes it rebuild once on the next compile
(which overwrites the scene). Edit the builder, not the scene.

- `GravityArenaBuilder`: shared helpers only (`BuildScene`, `Block`, `Make`, `Link`, materials, prefabs); the Gravity Arena map itself was removed
- `TriGravityAtriumBuilder` (small = 3 gravity families; Large = 6 families, families 3-5 mirror 0-2 through the
  hall centre via `Pt`/`Dir`; mirror doors bridge the two halves)
- `EndlessPavilionBuilder` (wrap-around walls: `Portal.worldWrap` + `WrapAroundCopies`; layout from `PavilionLayout` with a
  fixed seed, `LayoutSeed`)
- `ShiftingPavilionBuilder` (same generator, new layout every match: `ShiftingPavilion` builds it at runtime from
  `LobbyState.MapSeed`, re-rolled on Back to lobby). `PavilionLayout` is pure data and deterministic per seed, so it
  can be checked outside Unity (compile it against `UnityEngine.CoreModule.dll` in a net8 console app; avoid
  engine-only calls like `Bounds.Contains` in the checker)
- `HollowFortressBuilder` (hollow cube, a full arena on all six inner faces round a void; layout data in
  `FortressLayout`, one colour palette per face, breakable shoji screens via `BreakableScreen` + `PlayerCombat`)
- `SkybridgeBuilder` (folded space station: floor and ceiling 40 m apart joined by a hull bend on +X, ~10 scaffolding
  bridges at random spanning floor to ceiling, sideways gravity on their 26 m walkways with airlock doors at both ends;
  floor and ceiling furnished separately at random; layout data in `SkybridgeLayout`, fixed `Seed`)
- `PortalTestLabBuilder` (24 test rooms; signs show expected landings computed with `GravityAfterPass`)
- `MainMenuBuilder` (menu/lobby scene, `LobbyState` prefab, session prefab list)

When adding or changing map geometry, check it before handing over: overlaps between all boxes (including the
symmetric/mirrored copies), each portal has a host collider behind it and clear space in front, drop/flight paths
are clear, landing spots aren't on another portal, and simulate every portal pass with the gravity rule. These
checks have caught real bugs (two disconnected portal rings, chain drops, clipped fall paths).

## Working in this repo

- The user keeps the Unity Editor open, so batch-mode Unity can't run. Unity compiles/rebuilds when the user clicks
  into the Editor. `Editor.log` is not reliably flushed; don't depend on it.
- **Compile-check outside Unity** with `dotnet build` on a throwaway SDK-style csproj (netstandard2.1, LangVersion 9,
  NoStdLib, DisableImplicitFrameworkReferences) that compiles `Assets/GravityPortals/**/*.cs` and references every
  `<HintPath>` from `Assembly-CSharp-Editor.csproj` (make relative HintPaths absolute) plus
  `Library/ScriptAssemblies/*.dll` (Netcode, Transport, Unity.Services.*). Put it in the scratchpad. Shaders can't be
  checked this way.
- C# 9 only (no file-scoped namespaces, no global usings). One MonoBehaviour per file, file named after the class.
- PowerShell gotchas: variable names are case-insensitive (`$p` overwrites `$P`); here-strings with double quotes
  passed to `git commit -m` get split into pathspecs, so write the message to a file and use `git commit -F`.
  Scripted multi-line string replacements have silently dropped lines before; re-read after them.
- **Commits**: leave Unity's own churn out of commits: `Assets/Settings/URP-*.asset`, `Assets/DefaultVolumeProfile.asset`,
  `Assets/UniversalRenderPipelineGlobalSettings.asset`, `ProjectSettings/*BurstAot*.json`. Commit `.meta` files with
  their assets. Only commit/push when the user asks.
- **Releases**: Tools > Gravity Portals > Release bumps `PlayerSettings.bundleVersion`, builds Windows + Linux (Mono),
  pushes them to itch.io (`beardedgoblin/axisfall`, channels windows/linux) with the itch app's butler (players update
  through the itch app), and also
  zips them and copies them to `G:\My Drive\AXIS-FALL Builds` (Google Drive for desktop), which the user shares with
  a friend. Players on different versions are refused with a message.
